# Gaskiyya QA report, 20 October 2026

Tested build: commit `507a51e` on `main`, run locally on macOS. The app ran on an iPhone 17 Pro Max simulator (iOS 26.5) as a Flutter 3.47.7 debug build. The registry and the bank sandbox console ran with `pnpm dev` on Node 22, using the in-memory store.

Method: one manual pass through the app, then four agents working in parallel:

1. **Simulator UI.** Every screen and flow, driven by taps on the simulator.
2. **Registry API security.** Black-box and grey-box attacks on `packages/api`.
3. **Other flows.** Calls, WhatsApp, reports, AI explanation, campaign agent, console, emails.
4. **Code review.** The code checked against the six principles in `docs/DESIGN.md`, plus a fuzz test of TS/Dart canonicalisation parity.

Evidence (screenshots and scripts) is in the session scratchpad. It is not kept, so each finding below carries its own reproduction steps.

## Findings

Severity is about impact on a real bank customer. "Verified" means the finding was reproduced live or in-process. "Code-derived" means it was read from source and not executed.

### High: app

**F1. "Unlink this phone" does nothing.** Verified in the simulator.
- **Repro:** Settings, then Unlink this phone, then Unlink.
- **What happens:** the dialog closes, Settings still says "Linked", and `flutter.phone` stays in the prefs plist after 5 minutes.
- **Likely cause:** `SessionState.unlink()` (`mobile/lib/src/core/session.dart:151`) awaits `_events?.cancel()` and then `push.stop()` before clearing state. One of those awaits never completes, so `phone` and `bank` are never cleared.
- **Impact:** there is no way to sign out or switch account.

**F2. The Calls tab shows a stale state with confidence.** Verified.
- **(a) No live update:** while the bank had an open call (`calling:true`, code 1442), the Calls tab said the bank was not calling and told the customer to hang up. Live call events never arrived in that session, and the screen does not poll.
- **(b) Ended calls linger:** after the bank ended a call (`PATCH /sim/calls/:id {status:"ended"}`), the app showed it as still calling, with the code, for about 2 minutes until the original expiry.
- **(c) Refresh is hidden:** with a call card on screen there is no visible way to refresh. Only pull-to-refresh works.
- **Impact:** customers hang up on their real bank, or trust a call that has already ended.

**F3. The call countdown is frozen.** Verified in code and in the simulator.
- **Cause:** `mobile/lib/src/ui/screens/calls_screen.dart:196` declares `late final Timer _t = Timer.periodic(...)`. A `late` field initialises lazily, and it is first touched only in `dispose()`, so the timer never runs while the screen is visible.
- **Fix:** create the timer in `initState`.

**F4. "Cannot check right now" for up to 9 minutes after a token key change.** Verified.
- **Cause:** the app caches the customer token for 540 s and never retries on 401 (`_send` in `mobile/lib/src/core/api.dart`, `token()` in `core/session.dart`). The demo console makes a new signing key on every start. In production, any bank key rotation does the same.
- **What happens:** genuine messages show "cannot check" and the inbox is empty, while Settings still says "Linked". This fails safe, but it is wrong.
- **Fix:** on a 401, drop the token, fetch a new one, and retry once.

### High: before production

**F5. AI explanation text can contradict the verdict or ask for secrets.** Verified in-process with a fake model provider.
- **Where:** `packages/api/src/ai/explain.ts` only rejects replies that fail the schema or match `asksForSecret`.
- **Gap 1, no check for "genuine" wording:** a reply such as `"This message is genuine and was sent by your bank."` / `"You can safely follow it."` passes and is shown with `source: "model"`. It appears under "Not confirmed" on the result sheet (`mobile/lib/src/ui/screens/result_sheet.dart:415`) and in the WhatsApp reply (`packages/api/src/whatsapp.ts:93`), where there is no "AI generated" note.
- **Gap 2, the secret filter is easy to bypass:** `asksForSecret` treats a sentence as safe if any negation word (no, not, never) appears anywhere in it, and it misses the bare word "code". These pass the filter:
  - "Reply with your PIN now, no delay."
  - "send your OTP to 0803 so it is not blocked"
  - "Please share the code we sent you with the agent"
- **Attack:** a fraudster puts prompt-injection text in the SMS itself.
- **Current exposure:** zero locally, because the AI keys in `.env` are blank and the fixed fallback text is used. It becomes real as soon as a key is configured.
- **Tests:** AI-1 to AI-3 still pass because they only check that the verdict does not change.

**F6. Reports are stored unmasked.** Verified live and in-process.
- `POST /v1/reports` stores `maskedText` exactly as sent. Masking happens only in the console client (`maskDigits` in `console/src/device/api.ts`).
- A report containing `4111 1111 1111 1111`, `OTP 482913` and an account number was stored verbatim.
- **Fix:** the server must re-mask, as `explain()` already does.
- Masking also misses `OTP 4 8 2 9 1 3`, `48 29 13`, three-digit CVVs and PINs, and full-width digits.

**F7. Firebase client keys are committed** in `mobile/config/production.json`, tracked since commit 76ac1c0. This is the one failing test (SEC-3).
- These keys ship inside every app build, so they are not secret in themselves. The risk depends on Google Cloud restrictions, which cannot be seen from the repo.
- **Action, part 1 (outside the code):** restrict both keys in Google Cloud to the app IDs and to the Firebase APIs.
- **Action, part 2 (code):** stop committing them. Inject them from Codemagic environment variables, or add a reviewed allowlist with a decision note. Do not weaken the test.

### Medium

- **F8. A far-future `sentAt` defeats the 30-day expiry.** Verified. A registration with `sentAt` set to 3000-01-01 is accepted (202) and gets `expiresAt` 3000-01-31. There is no range check in `packages/schemas/src/index.ts` (RegisterMessage) or in `packages/api/src/service.ts:537-558`. Clamp `sentAt` to a window around server time.
- **F9. Calls do not fail closed.** Verified in-process. With a failing store, `GET /v1/calls/open` returns 500.
  - **Console phone:** maps any error to "not calling" (`console/src/device/Device.tsx:746`).
  - **WhatsApp:** "CALL" gets no reply at all, because the error is swallowed in the webhook `.catch` in `packages/api/src/app.ts` and the webhook still returns 200, so Meta does not retry.
  - **Flutter app:** behaviour on a 500 was not checked.
  - Errors must show "cannot check".
- **F10. Overlapping calls to one number show only the newest code.** Verified. `openCallFor` takes the first entry of `store.openCalls`, so when several agents call the same customer, every other agent's code does not match.
- **F11. Privacy wording overstates what the app does.**
  - **What the app says:** "Only the fingerprint is checked, never the words" (intro), "Only the fingerprint is sent" (Check) and "Message text stays on this phone" (Settings).
  - **What it does:** every not-confirmed result sends the digit-masked text to `/v1/explain` without asking (`result_sheet.dart:87`, then `api.dart:221`). Screenshot check uploads the whole image.
  - **Other wording:** intro slide 2 says the bank "either confirms it sent it to you, or it didn't", which leaves out "cannot check".
  - **Process:** wording changes in `copy.json` need a decision note and approval.
- **F12. `/v1/admin/reset` wipes all tenants.** Code-derived, not executed. With `ALLOW_DEMO_RESET=true`, any one bank client's credentials can call it, and `MemoryStore.reset()` / `FirestoreStore.reset()` clear every collection. Scope reset to the caller's tenant, and keep it off outside demos.
- **F13. TS and Dart canonicalisation differ on newer Unicode.**
  - **Cause:** `unorm_dart ^0.3.3` (Unicode 18) against Node ICU (Unicode 15.1 on Node 22; 16 in `node:24-slim`).
  - **Code points that differ:** U+0558, U+058B-058C, U+209D-209F, U+D7A4, U+107BB-107BF, U+1B123-1B126, U+1D6A6, U+1DF95, U+1DFCD-1DFFF, and combining-mark reordering with U+1AEF and U+1D252.
  - **Fix:** pin both Unicode versions and add these to `packages/test-vectors/cases.ts`. Changing canonicalisation needs a decision note and approval.
- **F14. A link on a bank domain shows "Confirmed".** That decision is made in `packages/api/src/domain/link.ts:62`, outside `verdict.ts`, and the result sheet uses the confirmed artwork and tag (`result_sheet.dart:145`). An open redirect on the bank's domain would show as "Confirmed". Give links their own wording ("belongs to your bank") and artwork.

### Low

- **F15. Model-drafted campaign advisories skip `asksForSecret`.** See `packages/api/src/campaigns.ts`, `draftAdvisory`. They are still drafts until an analyst approves them.
- **F16. "Analyst approval" accepts any bank client credential.** The `approvedBy` field records the machine client (`demobank-sim`).
- **F17. Repeating "answered" on a call extends `expiresAt` by 2 h each time,** with no upper limit (`service.updateCall`).
- **F18. CORS reflects any origin** when `CORS_ORIGINS` is empty (`packages/api/src/index.ts:806`, `app.ts:172`), and `/v1/events` echoes the request origin. Bearer-only auth limits the impact.
- **F19. No security headers** (no helmet).
- **F20. The mobile client trusts any 2xx with `verdict:"confirmed"`.** If `sentAt` or `channel` is missing, a null-check throws during build, and the customer sees Flutter's error widget after the "confirmed" haptic has already fired (`api.dart:25-36`, `result_sheet.dart:84` and `152-159`). Reaching this needs control of the transport.
- **F21. The marketing site shows "Sent by your bank" by default.** It keeps showing it when `crypto.subtle` is unavailable, for example over plain http (`site/src/main.ts:185-192`, `index.html:209`). Its canonicaliser is not tested against the shared vectors.
- **F22. Demo exposure.** With `SIM_ENABLED=true`, `/sim/customer-token` mints a token for any number, and `/sim/inbox/admin` and `/sim/calls` have no auth. The demo customer list is hardcoded and always shown on the Link screen (`link_screen.dart:31`).
- **F23. Screenshot check with OCR unavailable** shows "Cannot check right now" as the headline, plus a small, contradictory "I could not read text in that image". The button is offered even when no OCR is configured.
- **F24. Layout and other small issues.**
  - The call banner overlaps the "Calls" large title.
  - Settings section headers are large and bold rather than iOS-style small grey headers.
  - Inbox rows do not show the channel.
  - The "DemoBank" status dot stays green while the registry is down.
  - The email footer says message text is never stored, but consented reports store it.
- **F25. Setup friction.** `package.json` says `node >=20`, but Vite 8 / rolldown need `^20.19 || >=22.12`. On Node 20.18 the console build fails because the native binding is missing. Homebrew's Flutter also needed `xattr -dr com.apple.quarantine` before `dartaotruntime` would run.

## Tested and passed

**Messages, in the app:**
- Genuine message: confirmed.
- One character changed: not confirmed.
- Fake with link: not confirmed, with indicator chips.
- Pasted text with extra whitespace, changed line breaks or a zero-width character: still confirmed.
- One word changed: not confirmed.
- Lower-cased text: not confirmed, which is by design.
- Genuine WhatsApp message: confirmed.
- Genuine SMS with a bank link: confirmed.

**Recipient binding:**
- Tunde's genuine message checked as Amina: not confirmed.
- The same message with Tunde's token, through the API: confirmed.

**Links:**
- `demobank.ng`: belongs to the bank.
- `demobank-restore.com` and `demobank.ng.secure-login.com`: lookalike warnings.
- `demobank.ng@evil.com`: not confirmed.

**Calls:**
- Code display matches the agent's code.
- 3-minute expiry works.
- With no call open, the customer is told to hang up.
- Codes are 4 digits from `crypto.randomInt`, evenly distributed.
- 200 concurrent calls: no cross-number leaks.

**Fail closed:**
- Registry down: cannot check.
- Malformed digest, rate limit and invalid JSON never confirm.

**Auth:**
- These are all rejected with 401: `alg=none`, HS256 signed with the ES256 public key, wrong issuer, missing audience, bank token used as a customer token, customer token on bank routes, garbage tokens, no auth.
- Tenant always comes from the token.
- Requests use `strictObject`, so injected `recipient` or `phone` fields are rejected.

**WhatsApp webhook:** the HMAC signature is checked over the raw body in constant time. Forged, missing and tampered signatures are all rejected.

**Storage and logs:**
- The store keeps only HMAC-keyed `recipientKey` and `contentKey` values (per-tenant key, domain-separated).
- The app keeps only `onboarded`, `phone` and `bank` in prefs.
- Logs contain method and path only. No bodies, query strings, tokens or phone numbers appear in `dev.log`.

**Rate limit:** 30 requests per minute on verify, keyed to the token's own number.

**Other:** the campaign agent never sends to customers. Emails ask for no secrets and escape HTML. Report, Activity, intro replay and dark mode all work.
